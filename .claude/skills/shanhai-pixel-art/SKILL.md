# 山海錄 像素美術

本作沒有任何外部圖檔。所有圖都是程式在瀏覽器載入時畫出來的，分兩種：

| 種類 | 做法 | 檔案 | 詳細 |
| --- | --- | --- | --- |
| **精靈**：物品、裝備、頭像、敵人、狀態、特效、地圖節點、街上小人 | 手寫像素格（每格一個字元）＋調色盤，載入時轉成 CSS class `.ic-<id>` | `js/icons.js`、`js/icons_npc.js`、`js/icons_more.js` | 本文 |
| **場景**：城鎮平面圖、荒野、地城、區域圖、大陸圖 | 程式在低解析度像素緩衝上畫矩形與小精靈，載入時轉成 `.sc-<id>` | `js/scenes.js`、`js/scenes_town.js`、`js/scenes_map.js` | `references/scenes.md` |

畫精靈時讀完本文即可。畫場景前先讀 `references/scenes.md`。

為什麼要手寫像素格：AI 很難穩定產出風格一致的點陣圖檔，但寫出一格一格的字元圖、每格自己決定顏色，品質是可控的，而且能在 git 裡逐行比對修改。代價是一定要「畫完、放大看、修」，第一版通常不及格。

---

## 1. 格式

```js
def('np_qian', [            // id
  '...........dr...........', // 每列一個字串，一字元＝一像素
  '.........uuRruu.........', // '.'＝透明
  ...                         // 列數＝寬度＝尺寸（16 或 24）
], { M: '#4a1610' });         // 選填：這張圖自己的調色盤覆寫
```

- **尺寸**：物品、裝備、狀態、技能、地圖節點、街上小人是 16×16；頭像、敵人、命中特效是 24×24。每一列長度都要等於列數。
- **調色盤**：主調色盤 `PAL` 寫在每個圖示檔的開頭，三個檔案內容相同，`icons_more.js` 末尾多了幾色（`m` `i` `E` `9`）。**只用 PAL 裡已有的字元**，主色系是：墨與鐵灰（`0`–`5`）、骨白（`w` `W`）、朱紅（`d` `r` `R`）、玉綠（`j` `g` `G`）、葉綠（`k` `l` `L`）、舊金（`o` `y` `Y`）、皮革（`n` `b` `B` `t`）、紫（`v` `p` `P`）、銅（`e` `c` `C`）、火（`f` `F`）、石板藍（`u` `z` `s` `S`）、灰燼（`q` `a` `A`）、膚色（`x` `h` `H`）。每個字母都是「暗、中、亮」三階的一組。
- **同形換色**：同一個輪廓要出好幾種東西（三種礦石、兩種藥水、兩種戒指），就把輪廓寫成常數，用大寫字母 `M X N O Q` 當「暗→亮」的佔位，再各自用覆寫給顏色：

  ```js
  var POT = [ ... 用 M X N O Q 畫的瓶子 ... ];
  def('pot_hp', POT, { M: '#4a1610', X: '#6e2018', N: '#b5382c', O: '#dc6350', Q: '#f3b9a8' });
  def('pot_ft', POT, { M: '#1d3a2c', X: '#2f5a45', N: '#5f9a7a', O: '#93c9a8', Q: '#d6efe0' });
  ```

- **放哪裡**：新頭像放 `js/icons_npc.js`，其他新圖放 `js/icons_more.js`（照檔內分區的註解）。不要改 `js/icons.js` 的基礎圖，除非是在修那張圖本身。如果要開新檔，照 `icons_more.js` 的寫法：自帶 PAL、在 `<head>` 注入自己的 `<style id="...">`、用「包一層」的方式擴充 `window.SHL_ICONS`（`has/list/size/raw` 先查自己、查不到再交給原本的），並在 `index.html` 裡排在其他圖示檔之後。
- **命名**：`np_` NPC、`pl_` 玩家出身、`n_` 地圖節點、`w_ o_ h_ c_ g_ b_ a_ r_` 裝備部位、`t_` 招式、`s_` 技能、`st_` 狀態、`f_` 勢力、`fig_` 街上小人、`fx_` 命中特效、`ui_` 介面。物品直接用 `js/data.js` 裡的物品 id。
- **接上遊戲**：畫好後到 `js/data.js` 把對應資料的 `ic` 欄位指到新 id（物品、裝備基底、敵人、地點、勢力都有 `ic`；NPC 的頭像 id 就是 NPC id，街上小人用 `fig`）。介面用 `ico(id, 備用字, 尺寸)` 顯示，找不到圖會退回文字，所以沒接上不會壞，但也不會出現。

## 2. 畫法

### 共通原則

1. **在深色底上看得清楚**。遊戲格子底色是 `#1d1a16`，整體很暗。輪廓用最暗的那一階（`0`、`n`、`u`，或該物件自己最暗的顏色），裡面一定要有中間調和亮部，不要只靠黑線撐。
2. **光從左上來**。左上緣用亮階，右下用暗階。所有圖都一樣，放在一起才像一套。
3. **剪影先於細節**。縮到行囊格（32px，原尺寸兩倍）時只看得到外形和一兩個顏色。先確定外形一眼認得出，再加細節。
4. **一個重點色**。每張圖挑一個識別色（藥水的紅、玉珮的綠、商會的金），其他用灰、皮革、鐵這些安靜的顏色。
5. **不反鋸齒、不漸層、不留孤立雜點**。斜線用階梯；單獨一個不同色的像素，通常就是雜點。
6. **全部原創**。不要照著任何現有遊戲或圖包的圖描。

### 物品與裝備（16×16）

- 物件約佔 12–14 格，四周留 1–2 格空白，不然在格子裡會顯得擠。
- 長兵器、弓、槍斜著放（左下到右上），能用滿對角線長度。
- 同類物品要能分辨：短刃和長刀只差刀身彎度時，縮小後會分不出來，要再加刀穗、護手形狀這類差異。

### 頭像（24×24，胸像）

24 格寬的臉幾乎畫不出表情差異，**辨識度幾乎全靠頭部輪廓與道具**。大致的版面：

| 列 | 放什麼 |
| --- | --- |
| 0–5 | 帽子、髮型、頭巾、頭盔：最重要的辨識區，輪廓要各不相同 |
| 6–15 | 臉：寬約 12–14 格置中；眼睛在第 8–9 列，各 2 格，黑點加一點亮；左半用 `H`、右半用 `x` 做明暗 |
| 16–23 | 肩膀與衣著：衣領、徽章、職業道具（算盤、藥葫蘆、包袱架、刀柄） |

- **每個人至少要有一樣別人沒有的東西**：紅髮簪、眼罩、單片眼鏡、竹笠、巨大背架。光靠臉型分不出來。
- **衣服顏色要拉開**。之前五個人都穿石板藍，只能靠帽子分。新增角色前先看一下總覽圖已有哪些顏色。
- **道具不要被畫框裁掉**。裁一半的葫蘆會變成一團橘色。
- 同一個人的不同版本（玩家六種出身）要維持同一張臉型，只換帽子、衣領、道具。

### 敵人（24×24）

- 放大到約 190px 顯示在戰鬥畫面中央，所以可以有比較多細節，但剪影要兇：張口、獠牙、伸出的爪、發光的眼睛。
- 首領要比同區雜兵大一圈（佔滿畫框），並有一個發光或高彩度的重點（皇冠、裂縫透光）。
- 用正面或四分之三側面的胸像，不要畫全身小人，放大後會很空。

### 狀態與技能圖示（16×16）

- 在 16px 原尺寸也要讀得懂：一個符號就好（血滴、骷髏泡泡、裂開的甲片、螺旋），不要畫場景。
- 同一組的圖示要用不同的主色，玩家才能一眼分出流血和中毒。

### 命中特效（24×24）

- 大部分透明，只有一個粗、亮的形狀（刀光弧、衝擊星、爪痕）。會放大疊在敵人身上，細線會不見。

## 3. 畫完一定要看：檢查與看圖修圖

第一版幾乎都有問題（像別的東西、太暗、有雜點、兩張圖太像）。流程是：

1. **結構檢查**：

   ```bash
   node .claude/skills/shanhai-pixel-art/scripts/check.js np_ pl_
   ```

   參數是 id 或 id 前綴，不給就檢查全部。它會檢查每列長度、尺寸是否為 16 或 24、每個字元是否在調色盤裡、id 有沒有重複、舊的圖有沒有被弄丟。

2. **出總覽圖並且親眼看**：

   ```bash
   node .claude/skills/shanhai-pixel-art/scripts/sheet.js --scale 8 --out /tmp/claude-0/.../scratchpad/sheet.png np_qian np_new
   ```

   會在遊戲底色上把指定的圖放大排成一張 PNG，每張下面附 1 倍大小版本和 id。用 Read 工具打開那張 PNG 看。`--scale 8` 看細節，`--scale 2` 看實際遊戲裡的感覺；可以加 `--with np_` 把同類的其他圖一起排進來比較。輸出請放在 scratchpad，不要放進 repo。

3. **用這張清單挑毛病**，有問題就改那幾列，再回到第 1 步：
   - 不看 id，認得出它是什麼嗎？會不會被認成別的東西？
   - 和同類的其他圖放在一起，分得出來嗎？
   - 2 倍大小時，輪廓和重點色還在嗎？
   - 有沒有一團糊掉的暗色、孤立的雜點、被畫框裁掉的道具？
   - 光是不是都從左上來？

   **至少看兩輪、改兩輪。**第一眼覺得還行的圖，放到同類圖旁邊常常就不行了。

4. **在遊戲裡看一次**：開 `index.html`（可加 `?fresh=1&origin=hunter&fx=0`），走到會出現這張圖的畫面截圖確認。只在總覽圖裡好看的圖，放進行囊格或戰鬥畫面不一定好看。

5. **跑專案測試**：`node tests/e2e.js`。測試會檢查 console 沒有錯誤、文字沒有互相重疊。

6. **老實回報**：交差時列出哪幾張比較弱、弱在哪裡（例如「算盤的瞇眼看不出來，只能靠算盤認」），讓使用者決定要不要再修。不要把每張都說成很好。

7. **更新總覽圖**（選做）：`docs/design/` 下面放著各批圖的總覽（`icons-v025.png`、`portraits-v03.png`、`icons-v03.png`…）。新增一批時，用 `sheet.js` 另存一張新的總覽到那裡。
