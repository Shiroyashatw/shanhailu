## 0. 結論

1. **已拍板做「等待式」行動條**（題 1 甲）：你選指令時時間停住，其他人的條在你出手後才繼續跑。規則層仍是離散推進（不靠牆鐘計時），演出佇列、`?fx=0`、固定種子、e2e、模擬器都能沿用。
2. **它真正改變的是「速度有意義」**：現況每輪每人只出手一次，速度只決定先後；行動條下，快的敵人出手更多次。這會動到所有用現行戰鬥算過的數值（前線、剿匪），所以要 SPEC-ATB 先壓縮速度差，再由 ACC 重跑。速度沿用現算法並壓縮差距（題 2 甲）。
3. **已拍板新開第 2b 期**（題 4 乙）：放在第 2 期之後、3a 盜墓之前。不併進第 2 期同批開發，但規格與草稿現在就並行。SPEC-ATB、UI-ATB、LOC-ATB 已派（17:27）；DEV-ATB 等規格和草稿定稿再派。
4. **第一批開發（DEV-01～05、DEV-DROP）不必改**（題 5 甲），只在 DEV-02 完成標準補一句：`cflash` 節流寫在表現層（每秒 ≤3、間隔 ≥400ms，X12），不要綁回合結構。
5. **招式有輕重**（題 7 乙，非原建議）；**不做自動戰鬥**（題 6 甲）；**不做原型**（題 9 甲）。同伴在條制下自動出手、玩家只下戰術預設（題 8 甲）。
6. **17:26：順序條改成跑道式**（頭像沿軌道往終點跑，到終點行動、行動完回起點）。**17:44 題 3 拍板甲**：每個單位一個頭像、不限格數；超過 8 個就縮小重疊。
7. 誠實的提醒：等待式行動條在手感上仍接近「看得見順序的回合制」。招式輕重已納入本案；敵人行動多樣性仍可能是更大的深度來源，見第 8 節。

## 2. ATB 提案（暫定，細節歸 SPEC-ATB）

### 2.1 機制概要

| 項目 | 提案 | 理由 |
| --- | --- | --- |
| 核心模型 | **等待式、事件驅動**：規則層沒有牆鐘。每次你下指令，函式先處理你的出手，再把「刻」往前推，依序處理敵人出手，**直到你的條再次滿**才停。演出佇列照舊回放 | 保住「邏輯先結算、演出只回放」（UI-FX 原則①）、`?fx=0`、固定種子、e2e、b1-sim |
| 條 | 每人一條 0–100；每刻加 `有效速度`；滿 100 出手，出手後歸零（多出的不留）。同刻同滿：你先（沿用現行） | 簡單可驗算 |
| 速度來源 | 你：沿用 `playerSpeed()`（身法、負重、速度詞綴、疲累、之後的寒意）。敵人：沿用 `spd`。**兩邊先壓縮再用**：`有效速度 = clamp(10 + (速度 − 10) × K, 6, 16)`，K 暫 0.5 | 生活系統（負重、疲累、天候）自然接進戰鬥＝沙盒支柱；不壓縮會讓超載（×0.4）被打出 2.5 倍、守墓俑只剩一半火力。例見 2.2 |
| 跑條要不要暫停 | **已拍板題 1 甲：你選指令時完全暫停** | 網頁文字 RPG、hover 說明要讀、手機觸控；等待式也不吃 e2e |
| 跑道（17:26／17:44） | 每個角色的頭像沿軌道往終點跑，到終點就行動，行動完回到起點；不再是靜態排序格。蓄力、重擊用記號標在頭像上。條有變（失衡、速度變化）時位置立刻重算。滑過顯示完整名詞說明。**已拍板題 3 甲（17:44）**：每個單位一個頭像、不限格數；超過 8 個就縮小重疊 | 已拍板改跑道；顯示規則已定 |
| 條在哪裡看 | 跑道為主；敵人血條下一條細條；你的狀態牌一條細條。**畫面只用「行動條」「跑道」等全名，不用 ATB 縮寫** | 沿用 mumi 16:10：縮寫改全名＋hover |
| 技能／招式 | **已拍板題 7 乙：招式有輕重。** 重招式出手後較慢、道具與待機較快；回條位置與再填速度由 SPEC-ATB **招式輕重表**定。冷卻仍以你自己的出手次數計（`cds` 數字不用改） | 12 招式、3 技能要寫進輕重表 |
| 道具、待機 | 和攻擊一樣花一次出手；**已拍板題 7 乙**：道具與待機較快（回條細節歸招式輕重表） | 現況道具就是「耗一回合」（`ui.js:185`） |
| 防禦、遊身、鴉影 | 「本回合」改為**持續到你下一次出手前** | 效果範圍與現況最接近 |
| 流血／中毒／破甲 | 改以「拍」計：1 拍＝10 刻（一名速度 10 的人出手一次的時間），各 3 拍。雙方一致 | 以時間計才公平；快慢敵人不改毒傷總量 |
| 調息（被動） | 每拍回 2 生命 | 同上 |
| 蓄力與打斷 | 敵人**出手後立刻抽下一個意圖**（不再整輪統一抽）。蓄力＝它的下一次出手必重擊；跑道標出「重擊在你之前或之後」，這是主要的新玩法。盾擊、擒拿、破陣打斷＝取消蓄力；失衡＝該敵人條歸零並延後起算 | 讓跑道有決策價值 |
| 撤退 | 仍是一個行動；成功即離場。**失敗＝你的條歸零（損失一次出手），不再附贈全體追擊一輪**；SPEC-ATB 可補「失敗時敵人條 +X」維持代價。前線仍不可撤退 | 現況「失敗全體追擊」在條制下沒有對應物 |
| 開場先後手 | 長兵先制＝你的條開場即滿；伏擊＝你滿、敵方歸零；遇伏＝敵方滿、你歸零；一般開場條值由 SPEC 定（小亂數）。弓弩先射照舊 | 現行特例全部有對應 |
| 同伴（第 7 期） | 場上單位統一為「陣營＋條」。同伴有自己的條與意圖；預設自動出手（戰術預設），要不要停下等你下令見題 8。**本期只要求資料結構不寫死「只有你一人」** | 同伴不必重做戰鬥，UI-COMP 只多一種頭像 |
| `?fx=0` | **保留**。只關演出回放；條制照常推進（無牆鐘，所以不影響結果） | e2e 靠它 |
| 自動戰鬥 | **現況沒有，第一版也不做**；只在規則層留「給定決策器推進到下次輪到你」的介面（測試與模擬用） | 題 6 |
| 存檔 | `S.combat` 加條值、拍數、陣營欄位；舊存檔本來就不相容，照現行處理 | 無額外成本 |
| 保持不變的介面 | `startCombat(ids, ctx, opts)`、`combatAction(kind, arg)`、`combatActions()`、`combatOrder()`、`S.combat.round`（改為「你的第 N 次出手」）、`data-testid`（order、round、act-\*、enemy-\*、intent-\*） | DEV-04 與 e2e 不被迫同步改 |
