## 3. 新的文字檢查方式（取代舊的自查，每張都要做）
舊方法的漏洞：只看 render.js 的整體 0 issues，加上整張縮小後的 PNG 目視，小字溢出、被 overflow:hidden 裁掉、斷行錯誤都看不出來；從現行畫面截來的圖片裡的文字，DOM 也檢查不到。

新方法：
a. DOM 自動檢查，在 render.js 加上以下項目，對每個文字節點都跑：
   - scrollWidth>clientWidth 或 scrollHeight>clientHeight，視為溢出。
   - 文字框超出任何 overflow:hidden 祖先或畫布邊界，視為被裁切。
   - 兩個文字框兩兩比對，交集大於 0 就算重疊，徽章壓到文字也算。
   - 行數檢查：用 getClientRects 數行數；標籤、按鈕、數值應該是 1 行，多出來就是錯誤。
   - 孤字：最後一行只剩 1 個中文字或標點。
   - 一個詞或「×1.08」這類數值被拆到兩行。
   - 字級小於 16px（腳註另外列出例外）。
   任何一項不為 0 都要修到 0。在報告中附上每張圖各項的計數。
b. 放大目視：把每張 PNG 切成 4–6 塊、放大 2 倍，逐塊用 Read 打開檢查。截圖或點陣圖裡的文字特別看。
c. 用詞 grep：在 html/src 中搜尋禁用舊詞，結果要是 0。
d. 每張圖在檢查表記一行：檔名 | DOM 各項計數 | 放大檢查 OK | 改了什麼。
