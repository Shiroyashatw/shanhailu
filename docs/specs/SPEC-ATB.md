## 0. 結論（先看這裡）

1. **等待式行動條**：你選指令時所有條停住；你出手後，其他人的條才往前跑，跑到「你的條再次最先滿」就停。規則層仍是離散事件推進（沒有牆鐘），演出佇列、`?fx=0`、固定種子、e2e、模擬器全部沿用。
2. **速度壓縮**：`有效速度 = clamp(10 + (速度 − 10) × K, 6, 16)`，**K = 0.5**【新，驗算掃 0.35／0.5／0.65】。全場最快對最慢：現行 14 對 4 ＝ **3.5 倍**；壓縮後典型 12 對 7 ＝ **1.71 倍**，疊滿疲憊與寒意的極端 12 對 6.36 ＝ 1.89 倍；下限 6 保證最壞 ≤ 2 倍（12÷6）。敵人彼此：14 對 5 ＝ 2.8 倍 → 12 對 7.5 ＝ **1.60 倍**。
3. **招式輕重**：每個行動有「後搖」`W`（出手後條回到 `100 − W`）。普攻 `W=100`；重招 115–140；道具 70、待機 60、防禦 80。重招多等最多 40％，道具少等 30％（§9）。
4. **撤退失敗**：你的條退到 −20（`W=120`），敵人條不動；比現行「失敗＝白丟一手」略重（§6.2）。前線仍不可撤退。
5. **回合語意對照表在 §5**（定案）：舊「回合」取消，次數類＝**手**（冷卻、本回合、第 N 手、蓄力、意圖皆按本人出手），時間類＝**拍**（流血、中毒、破甲、調息按全場共用的拍，1 拍＝10 刻；畫面暫稱「息」）；失衡、先制、伏擊、遇伏、撤退失敗以「條的起始位置與後退量」表達（§4.3、§8.0）；**狂怒是狀態，不是意圖**。
6. **跑道（已定 17:44，mumi 選甲）**：每個單位一個頭像，**不限格數**；超過 8 個時頭像縮小並重疊，位置越靠終點越上層，同位置照平手規則（§8.0.1）。頭像位置＝行動條（§8.0）。內部仍推演接下來至少 8 次出手（`order`），**只供預測列、預演與決策器用，與頭像數量無關**；預測列要不要顯示仍待決（Q-ATB-11）。**選目標與編號已定 17:48（§8.0.2）**：頭像不能點選，點敵人狀態牌或用按鍵；敵方單位有編號小章，開場固定、不回收。
7. **驗算要同時守住**：K2 前線起手・平民 20–40％、古窯清理級 ≥ 70％（§13）。ATB 內部參數先調，不夠才動 SPEC-02 §10.5（Q-ATB-8）。
8. 待決題 9 題（§15），每題有 ★。
8. 待決題 11 題（跑道做法不在其中，已定 17:44）（§15，只列玩法取捨），每題有 ★。語意類問題（LOC 5 題）已在 §5、§9、§8.0 定案。

### 1.2 保持不變（開發不要動）

- 傷害、命中、會心、護甲折算、閃避、防禦減傷：**全部沿用** `strike()`、`enemyAct()`、`useTech()`、`useSkill()` 的公式。

## 2. 名詞與符號

| 符號 | 意思 |
| --- | --- |
| 條 `b` | 每個單位一條，滿值 `FULL = 100`；可為負（後搖尚未還清）。 |
| 有效速度 `v` | §3.1 壓縮後的速度；每「刻」條增加 `v`。 |
| 刻 | 規則層的時間單位（實數）。速度 10 的單位 10 刻填滿 100。 |
| 拍 | `BEAT = 10` 刻。時間類狀態（流血、中毒、破甲、調息）以整拍邊界結算。 |
| 手 | 你的一次出手。冷卻、`S.combat.round` 以手計。 |
| 後搖 `W` | 一個行動的「等待量」：出手後 `b = 100 − W`。`W=100` 為標準（出手後歸零）。 |
| 出手者 | 條最先到達 100 的單位。 |

「一次出手」只在「該單位真的執行一個行動」時成立：失衡、被取消的蓄力不算出手。

## 3. 條公式

### 3.1 有效速度

```
v_raw(你)  = playerSpeed()                    // 【沿用】10 × speedMult() + (身法−10)×0.4 (+ 狩獵時追蹤熟練度×0.05)
v_raw(敵)  = ENEMIES[id].spd                  // 【沿用】
v          = clamp(10 + (v_raw − 10) × ATB_K, ATB_MIN, ATB_MAX)
ATB_K = 0.5   ATB_MIN = 6   ATB_MAX = 16      // 【新】
```

- 你和敵人**走同一條公式**，壓縮不偏袒哪邊。
- `speedMult()` 沿用現行：負重檔 × 速度詞綴 × 疲累（≥80 → ×0.85）；v0.5 起再乘寒意階（§7）。
- 計算結果保留 2 位小數顯示（`round(v×100)/100`）；內部用原值。

### 3.2 壓縮前後（設計意圖）

| 對象 | 現行 `v_raw` | 壓縮後 `v` | 對「速度 10」的出手頻率（現行→壓縮） |
| --- | --- | --- | --- |
| 毒蟲（最快敵人） | 14 | 12.00 | 1.40 → 1.20 |
| 身法 20 輕快玩家 | 14 | 12.00 | 1.40 → 1.20 |
| 沼屍、守墓俑（最慢敵人） | 5 | 7.50 | 0.50 → 0.75 |
| 蹣跚玩家（過量） | 4 | 7.00 | 0.40 → 0.70 |

- **最快對最慢**：現行（毒蟲對蹣跚玩家）14÷4 ＝ **3.50 倍**；壓縮後 12÷7 ＝ **1.71 倍**。敵人之間 14÷5 ＝ 2.80 → 12÷7.5 ＝ **1.60 倍**。
- 疊滿的極端（蹣跚 ×0.4、疲憊 ×0.85、凍僵 ×0.8、身法 8）：`v_raw = 10×0.272 + (8−10)×0.4 = 1.92`，`v = 10 + (1.92−10)×0.5 = 5.96 → 夾到 6`；對毒蟲 12÷6 ＝ 2.0 倍（理論最壞）。
- **設計意圖**：速度要「有感但不壓倒」。①蹣跚玩家對速度 10 的敵人，每一手要挨 1.43 次（現行 2.5 次）——負重仍然痛，但不是被打死；②窯屍（`v=8`）每一手只出 0.8 次，比現行「每手 1 次」弱，這是行動條相對現行的預期差，由 §13 的 K2 重跑檢查有沒有讓前線太容易。
- 下限 6、上限 16 是**保險**，正常玩法碰不到。

### 3.3 手算例（開發驗收用，AC-ATB-3）

你 `v=10`、窯屍 `v=8`（`v_raw=6`）。窯屍起始條 24，你 100（一般開場）。你出手普攻（`W=100`，條→0）。

- 窯屍到滿：`(100−24)÷8 = 9.5` 刻；你到滿：`100÷10 = 10` 刻 → **窯屍先出手**（t=9.5）。
- t=9.5 窯屍出手，條→0；你的條 = 95。你在 t=10 到滿（再 0.5 刻）。窯屍此時條 = 4。
- 你第 2 手在 t=10 → 條 0；你第 3 手在 t=20；窯屍第 2 次出手在 `9.5 + 12.5 = 22`。
- 所以 t∈[0,22]：你出 3 手，窯屍出 2 次（比值 0.67，比 §3.2 的 0.8 低只是因為起始條與取整窗口，長期趨近 0.8）。

### 4.4 平民的基準

平民（素質全 10、制式裝備＋藥水 ×4）：總重 `3+4+6+4 = 17`，`carryCap = round((40+10×4)×1) = 80`，`17÷80 = 0.2125 ≤ 0.4` → **輕快**，`speedMult=1`，`v_raw=10`，`v=10`。所以 K2 前線平民的壓縮不改變自己的速度，只改變敵人的速度。（驗算要讀實際 `loadBand()`，不是假設。）

## 5. 回合語意對照表（開發與本地化共用；LOC 短版見 `handoff/ATB-loc-handoff.md`）

> 本節是 LOC-ATB 與 GDD 用語改寫的唯一依據。**每一種「回合」用法都已定案**為下列三種語意之一：
> **甲＝按本人出手**（從該單位自己的下一次出手算起，數他自己出手幾次）｜**乙＝按拍**（固定長度的戰鬥時間，全場共用，與誰出手快慢無關）｜**丙＝按全場**（整場戰鬥有效）。

### 5.1 單位詞與時間單位（定案）

| 項目 | 定案 | 理由 |
| --- | --- | --- |
| 「回合」整詞 | **取消**。規則與資料不再有「輪」。次數類改「手」（你的出手次數），時間類改「拍」 | 條制沒有「全員各一次」的一輪 |
| 手 | 你的一次出手（道具、待機、防禦、撤退失敗也各算一手；無效指令不算）。玩家標籤「第 N 手」【待本地化，LOC ★甲】；說明文寫「N 次出手」 | 同 §2 |
| 拍 | **1 拍 ＝ 10 刻 ＝ 一名 `v=10` 的單位把條從 0 填到 100 的時間**（定案，`BEAT = 10`）。拍只在「整拍邊界」結算（`T` 跨過 10 的倍數） | 速度 10 是基準，一拍＝基準單位的一次出手時間 |
| 刻 | 規則內部時間單位；**不出現在玩家畫面**（會被讀成時辰） | 與已定名詞「清晨／白天／黃昏／黑夜」「24 小時制」避免撞字 |
| 息 | 玩家畫面上「拍」的**暫定字串**（LOC ★乙，待 mumi 與本地化確認）。規格與程式內部一律叫「拍」；文件固定寫「拍＝畫面的息」 | 一物一名；避免「拍」流到畫面 |
| 行動條／跑道／出手順序 | 行動條＝每個單位自己的進度（細條）；**跑道**＝上方全員一起跑的畫面（17:26 改）；**出手順序**＝預測列（是否顯示待決 Q-ATB-11，§8；跑道本身已定 17:44：每單位一個頭像、不限格數）。指令按鈕列暫稱「指令列」【待本地化，LOC 建議由「行動列」改名】 | 與 LOC-ATB 一致 |

### 5.2 為什麼持續傷害與狀態按「拍」而不是「受影響者自己的出手」（定案，回答 LOC 待回答 4）

1. **公平**：流血 −2、中毒 −3 若按受影響者自己的出手次數，**快的單位同樣時間內被扣更多次**、慢的單位少扣；毒傷總量就變成速度的函數，同一把毒油對毒蟲比對沼屍強 1.6 倍（12÷7.5）。按拍，同樣的時間扣同樣的量，**不因速度偏袒任何一邊**。
2. **輕重行動不被扭曲**：若按自己出手計，喝藥（`W=70`）會讓流血「少過一點時間卻扣同樣次數」，重招（`W=140`）反而讓流血多撐 1.4 倍時間——重招變成流血的解藥，與 §9 的輕重意圖相反。
3. **調息**：每拍回 2，慢的人（蹣跚）每手經過更多拍、回得更多——這正好補償負重的慢；若按出手計，慢的人回得少，雙重懲罰。
4. **接受「快的人在同一時間內承受相同總量」**：不採甲。**冷卻**是唯一按本人出手的持續時間，因為它是「你自己的招式要隔幾次才能再用」的節奏，不是時間。
5. **缺點**：玩家要多學「拍／息」。緩解：只有流血、中毒、破甲、調息四處會看到，hover 一律用「剩 N 息」。

### 5.3 對照表（定案）

「語意」欄＝上述甲／乙／丙。

| # | 舊（回合制）用語 | 新（行動條）寫法 | 語意 | 機制定義 |
| --- | --- | --- | --- | --- |
| 1 | 招式／技能「冷卻 N 回合」 | **冷卻 N 次出手**（表頭「冷卻（次出手）」，單格只放數字） | 甲 | 出手時 `cds[id] = cd + 1`；**你的每次出手結束時所有 `cds` 減 1**（與現行 `endRound` 同結果）。敵人出手不減。冷卻 N＝你之後的 N 次出手不可用，第 N+1 次可用。 |
| 2 | 防禦／遊身／鴉影「本回合」 | **到你下次出手前** | 甲 | `defend`／`evade`／`shadow` 在你出手時設定，**在你下一次出手開始處理時清除**。遊身「下一擊 +30%」（`next=1.3`）沿用：你下一次攻擊類出手生效後恢復 1。文字寫在效果之後：「閃避 +60%（到你下次出手前），下一擊 +30%」。 |
| 3 | 擒拿／盾擊「打斷對方這回合的行動」 | **打斷：取消蓄力，使對方失衡** | 甲（失衡以條計） | 第 10 列：取消蓄力、重抽意圖、`b=−50`。「對方下一次出手」只是效果的結果，不是計數單位。 |

## 6. 出手與推進

### 6.1 一手的處理流程（`combatAction` 改成這樣）

```
combatAction(kind, arg):
  1. 驗證與現行相同（技能冷卻、目標、道具可用）。無效指令不耗條、不推進。
  2. 清除你上一手留下的 defend／evade／shadow；再依本次行動設定新的。
  3. 處理你的出手效果（strike／useTech／useSkill／useItem／defend／wait；公式沿用）。
  4. 你的條 b = 100 − W(行動)    // §9；撤退失敗用 §6.2
     所有 cds 減 1；acts++。
  5. 若敵人全滅 → victory()；若你死亡 → checkDeath()。
  6. advance()：重複直到「你的條最先滿」或戰鬥結束：
       a. 對每個存活單位算 t_i = max(0, (100 − b_i) ÷ v_i)；
       b. 取最小 t；平手依 §8.3；
       c. 推進 Δt=t：所有條 += v×Δt；T += Δt；途中每跨過整拍邊界依 §5.3 第 16 列 結算；
       d. 若出手者是敵人：失衡（b<0 不可能滿；已由 b=−50 處理）；否則 enemyAct(e)；
          e.b = 100 − W_e；e.guard 規則沿用；rollIntent(e)；狂怒檢查（§5.3 第 11 列）；
          檢查你是否死亡／敵人全滅。
  7. 回傳給介面：新狀態＋FX 佇列（演出照放；演出中再按＝立刻收尾，沿用）。
```

- 「出手者是你」＝等待輸入，`advance()` 停止，**所有條不動**。
- 一手之內若你連續擊殺所有敵人，直接 `victory()`，不進 `advance()`。
- 同一刻多個敵人同時滿條：依序出手（§8.3 次序），每次出手後重查你是否死亡。

## 8. 跑道與預測列（出手順序）（跑道做法已定 17:44）

> **跑道做法已定 17:44（mumi 選甲，製作人轉述）：每個單位一個頭像，不限格數；超過 8 個時頭像縮小並重疊（§8.0.1）。** 17:25 的「8 格順序條」已被取代，原「只顯示前 8 個」「接下來 4 手」兩個選項作廢。本節把位置規則定案，並**保留推演演算法**作為內部 `order`：它只供預測列、預演與決策器用，**與頭像數量無關**。預測列是否顯示仍待決（Q-ATB-11）；顯示幾格（4 或 8）是 UI 的事，不影響規則層。

### 8.0 跑道位置規則（定案）

- 每個單位一個頭像，**不限格數**（§8.0.1；沿用現行字符 `g`；你＝金色）。**顯示位置 `x = clamp(b, −50, 100)`**（v0.1.3；v0.1.2 是夾到 0）：**0＝起跑線、100＝出手線**，**−50…0 為後搖區**（起跑線左側）；真實 `b` 照常計算，`b < −50` 時頭像釘在 −50 並加「«」（§8.0.3）。條滿（`b≥100` 且最先）＝到出手線＝輪到出手。誰先出手一律由 §8.1 的 `t=(100−b)÷v` 決定，**不看畫面位置**。
- **出手後頭像回到 `100 − W` 的位置**（即 `b = 100 − W`）：普攻、平招 `W=100` → 0（起跑線上）；輕行動與輕招 `W<100` → 起跑線右側 `100−W`（待機 60→40、道具 70→30、防禦 80→20、遊身與鴉影 70→30、擒拿 80→20、盾擊 90→10）；重招 `W>100` → 後搖區 `100−W`（−15…−40，例：重劈 −30）。後搖區的頭像照常往右跑，過了起跑線才算還清後搖。
- **起始位置與後退量**（對應 LOC 待回答 5；數值見 §4.3）：

| 情境 | 你的位置 | 每個敵人的位置 | 語意（給本地化） |
| --- | --- | --- | --- |
| 一般開場 | 終點（100） | `ri(0,40)`（起點到 40％之間） | 你先出手 |
| 先制（長兵 25） | 同一般開場；**第 1 手出手後只回到 25，不是 0**（`W` 減 25） | 同一般開場 | 先出手，且第一擊後恢復快 |
| 伏擊（追蹤 50、`r_strike`，`stun=1`） | 終點 | **`b=−100`**（超出後搖區：畫面釘在 −50 並加「«」，直到真實 `b ≥ −50`） | 措手不及：對方開戰時還要多等一整手 |
| 遇伏 | **起點（0）** | **終點（100）**，依有效速度高→低各出手一次，出手後回到 `100−W_e` | 被先打一輪，你要從起點追 |
| 失衡 | — | 被打到 `b=−50`（畫在後搖區最左，**不加「«」**），再走 50 才到起跑線、共 150 才到出手線 | 失衡：回到起點並多等 50 |
| 撤退失敗 | 回到 `b=−20`（後搖區） | 不動 | 撤退失敗：多等 20 |

### 8.0.1 頭像數量、縮小與重疊（**已定 17:44**，mumi 選甲，製作人轉述）

- **每個單位一個頭像，不限格數**：你＋場上所有存活的敵人（之後同伴也算）都各一個。規格**沒有任何「最多幾個頭像」的上限**，也不寫死「只有你一人」。現行內容場上敵人最多 2 隻，所以平常是 3 個頭像；「8」在本節只出現在下面的縮小起點，**不是上限**。
- **縮小**（比例是規格值，像素由 UI-ATB 定、可調）：頭像數 `N ≤ 8` 用標準尺寸；`N > 8` 時縮小為 `s = max(0.5, 8 ÷ N)` 倍標準尺寸；`N > 16` 時不再縮小（`s=0.5`），只靠重疊。字符 `g` 與你的金色在縮小後仍須辨認；縮小時狀態記號可合併成角標（UI 定）。
- **重疊時誰蓋在上面**（上層→下層）：
  1. **位置 `x` 越靠終點越上層**（`x` 越大越上）。
  2. **畫面位置相同（`|Δx| < 1e-9`；`x` 是夾到 [−50, 100] 的顯示位置，`b ≤ −50` 的單位都釘在 −50、視為同位置）時照 §8.3 平手規則排上下**：你 → 有效速度高者 → 敵人編號 `no` 小者，**先出手的在上層**。（疊層比的是顯示位置；§8.3 比的是出手時間，兩者分開，見 §8.0.3。）
  3. 例外只有一個：**輪到出手的頭像（在終點）永遠在最上層**（等待式時就是你）。
- **與預測列、8 次推演無關**：頭像數量由場上單位數決定；§8.1 的「8 次出手」只是**預測、預演與決策器**的推演深度，**不限制頭像數量**，頭像是否出現在推演的 8 次之內也**不影響它在跑道上的顯示**。
- **新內容守則【暫】**：已知內容（前線每波、地城每層、盤查戰、剿匪伏擊）同時存活的敵人 ≤2，所以現行最多 3 個頭像。新內容同時存活敵人（含增援、召喚）建議 ≤6，超過要經數值設計師核准；UI 防呆仍須撐到 `N>16`（不再縮小、只重疊）。
- 重疊時怎麼辨認、怎麼選目標：見 §8.0.2（UIUX 答覆，已定 17:48）。

### 8.0.2 辨認與選目標（UIUX 答覆，**已定 17:48**；編號規則為數值設計師裁定）

**2. 編號小章。** 每個**敵方單位**有一個編號小章（`1`、`2`、`3`…），狀態牌與跑道頭像用同一個號碼。

**3. 玩家外框。** 你的頭像外圍加一圈**不會被遮住的外框**。這圈外框**不影響位置、不影響疊層規則**（疊層仍只看 §8.0.1 的 `x` 與平手規則；外框畫在最外層、不參與遮擋判定）。

### 8.0.3 後搖區、範圍、平手、後搖剩餘量（v0.1.3，回答 UI-ATB「給數值設計師」1、2、3、6）

**1. 顯示範圍與「«」**：顯示位置 `x = clamp(b, −50, 100)`；`−50…0` 是後搖區。**「«」只在真實 `b < −50`（嚴格小於）時顯示**，頭像釘在 −50；真實 `b` 照常計算、照常往右跑，**一直顯示到真實 `b ≥ −50` 為止**；`b = −50`（失衡、打斷剛打完）**不加「«」**。例：伏擊 `b=−100`、`v=10`，5 刻後 `b=−50`，「«」消失，頭像從最左端開始往右走。

**2. 最低位置值（現行內容）**：

| 來源 | `b` | 備註 |
| --- | --- | --- |
| 伏擊開場（敵人） | **−100**（通式 `−100 × stun`） | 現行內容 `stun ≤ 1`（`r_strike`、追蹤 50），所以最低 −100；日後若 `stun ≥ 2` 更低，照常計算，畫面一樣釘 −50 加「«」 |
| 失衡、打斷（敵人） | −50（設定；原本更低則維持 −100） | 不加「«」 |
| 重招出手後（你） | −15…−40 | 崩岩擊 −40 最低 |
| 撤退失敗（你） | −20 | |
| 敵人一般出手後 | 0 | `W_e=100`；若 Q-ATB-2 選乙（重擊 `W_e=120`）則 −20 |

**→ 現行內容中最低就是 −100（只有伏擊開場的敵人），玩家最低 −40；沒有比 −100 更低的值。**

**3. 後搖與平手是兩件事，分開判定，不衝突**：
- **平手（§8.3）**比的是**出手時間** `t = (100 − b) ÷ v`，用**真實 `b`**，後搖（`b<0`）**不夾到 0**；所以後搖中的單位 `t > 100/v`。
- **疊層**比的是**顯示位置 `x`**（夾到 [−50, 100]）：`x` 相同時才用 §8.3 的順序（你 → 速度高 → `no` 小）決定誰在上。
- v0.1.2 寫過「後搖中的單位 `x` 都夾在 0」，**作廢**：畫面照真實位置顯示到 −50；`b ≤ −50` 的單位都釘在 −50，視為同位置。

**4. 後搖剩餘量 N（hover 用；是否顯示由 UI 決定，數值面建議顯示）**：
- 後搖條量 `D = max(0, −b)`（條量，不是時間）。
- **`N（息）= D ÷ (10 × v)`**，`v` 是目前有效速度（速度變就重算）；到後搖還清（`b` 回到 0）還要幾息。
- 顯示規則：`N < 1` 進位到 0.1；`N ≥ 1` 進位到 0.5；最多 3 個字元（例：`0.3`、`1.5`、`10`）。hover 句式：「後搖 N 息」（`息` 暫定，待本地化；不寫刻）。
- 換成「手」：`N（手）= D ÷ 100`（該單位自己一次標準出手的幾分之幾），與速度無關；多半 <1，**不建議顯示**。
- 手算：重劈後 `b=−30、v=10` → `D=30`，`N = 30÷100 = 0.3` 息（3 刻）；伏擊 `b=−100`、窯屍 `v=8` → `N = 100÷80 = 1.25` → 顯示 1.5 息；失衡 `b=−50、v=10` → 0.5 息。

**5. 敵人狀態牌的細條**：填滿比例 `clamp(b, 0, 100) ÷ 100`；`b < 0` 時為**空條＋後搖記號（狀態記號「搖」）**，不另畫負值。規格接受（UI-ATB 草稿即如此）。

### 8.1 推演演算法

輸入：所有存活單位的目前 `b`、`v`；每個敵人的目前意圖與其後的 `pat` 順序；你下一手的假設行動。輸出：接下來至少 8 次出手（含你），**且至少延伸到「你」的下一次出現為止**（頭像很多、前 8 次裡沒有你時照樣能算「先於你／後於你」）。這 8 次只是**預測、預演與決策器的推演深度，跟頭像數量無關**（§8.0.1）。

```
strip(units):
  state = copy(units)            // b、v 都用目前值
  out = []
  while out.length < 8 或 「你」出現次數 < 2:
    for each u in state: t_u = max(0, (100 − u.b) ÷ u.v)
    pick = min t（平手 §8.3）
    advance all b += v × t_pick
    out.push({ who: pick, t: 累計 t, intent: (敵人且是它的第一次出現) ? 目前意圖 : null })
    pick.b = 100 − W_next(pick)   // 敵人：用該意圖的 W（預設 100）；你：假設「普攻」W=100
  return out
```

- 第 1 格就是「現在輪到的人」（等待輸入時一定是你，t=0）。
- 整拍邊界的 DoT 不影響順序，推演忽略（但 DoT 致死會讓格子失效，見 §8.4）。
- 你之後各格用「普攻 W=100」假設（因為不知道你會選什麼）。

### 8.2 手算例（AC-ATB-8）

你 `b=100, v=10`；窯屍 `b=24, v=8`（意圖攻擊）；毒蟲 `b=60, v=12`（意圖攻擊）。全部後搖 100：

| 2 | 毒蟲 | 3.33 | `(100−60)÷12` |

### 8.3 平手怎麼決定

兩個以上的單位在同一刻滿條（`|t_a − t_b| < 1e-9`）時依序：

1. **你先**（沿用現行「同速你先」）。
2. **有效速度高者先**。
3. **敵人編號 `no` 小者先**（`no = idx + 1`，開場固定、不回收，§8.0.2）。

平手一律用真實 `b`：`t = (100 − b) ÷ v`，後搖（`b<0`）不夾到 0；夾值只用在畫面疊層（§8.0.3）。

### 8.4 速度變化與重算

預測列在下列時機**整條重算**（不是補差額）：你出手後、任一敵人出手後、敵人死亡、意圖改變、失衡／打斷、疲累跨 80、負重檔改變、撤退失敗。重算結果立刻覆蓋顯示；格子重排的動畫由 UI 定。

## 10. 意圖小標與狀態記號

**意圖**＝敵人「下一次出手要做什麼」，由 `rollIntent()` 抽出，**只有下面 8 種**。**狀態**＝單位身上的持續效果（失衡、狂怒、破甲、流血、中毒、後搖），**不是意圖**，不占意圖欄、不進「意圖小標」，用狀態記號標示。**狂怒是狀態（定案，回答 LOC 待回答 6）**：它是首領半血時的一次性旗標（`raged`），影響之後所有意圖的傷害，但自己不是「下一次出手要做的事」。

字串暫定，**【待本地化】**；小標用 LOC ★甲：沿用現行 2 字全名（窄格改 1 字交 UIUX）。

## 12. 決策器介面（給模擬與測試；第一版不做自動戰鬥）

```
// 規則層暴露（不進 UI）
combatView() -> {
  you:   { hp, max, fat, b, v, cds, speedMult },
  foes:  [{ idx, no, hp, max, b, v, intent:{k,range}|null, charged, guard, stag, bleed, poison, brk, raged }],
  order: [{ who, no, t, intent|null }]   // §8.1 的推演（至少 8 次出手，且延伸到你的下一次出現；只供預測／預演／決策器，與頭像數量無關）
  acts:  combatActions()
  peek(actionId) -> order[]          // 預演：若選該行動的預測列

combatDecide(decider, opts) // opts: { maxActs = 200 }
  // 每次輪到你時呼叫 decider(view) -> { kind, arg, target? }，直到戰鬥結束；`target` 用編號 `no`（1 起算，對應 `setTarget(no−1)`），不得指向已死亡或逃走的單位
  // 回傳同 combatAction 的結果；不經過 UI，不產生 FX 回放
```

### 13.2 決策器

- **A（主）**：沿用 `fight()` 的規則，但「`heavyIncoming`」改為「**預演選防禦（`W=80`）後，敵人的重擊在預測列中位於你下一格之前**」；喝藥門檻（生命 ≤ 40％）、打斷、範圍技、疲累 ≥76 改普攻等規則不變。喝藥、待機等輕行動照 `W` 自然生效。
- **B（對照）**：完全沿用現行 `fight()`（只看意圖，不看預測列；有重擊意圖就防禦）。
- 兩者都報，主判準看 A；B 用來看「不看預測列的人」會不會太慘或太輕鬆。

### 13.3 敏感度掃描（所有以 K2 起手・平民與清理級報）

| 參數 | 掃描值 | 中心 |
| --- | --- | --- |
| `K` | 0.25、0.35、0.5、0.65、0.75 | 0.5 |
| 重招 `W` 的「超過 100 的部分」倍率 `h`（`W' = 100 + (W−100)×h`） | 0.5、0.75、1、1.25 | 1 |
| 輕行動 `W` 的「少於 100 的部分」倍率 `l`（`W' = 100 − (100−W)×l`） | 0、0.5、1、1.5 | 1（l=0 即所有輕行動都是 100） |
| 撤退失敗 `W_retreat` | 100、120、140 | 120（只對 S4 與地城，K2 不撤退） |
| 失衡條 `STAG_B` | −25、−50、−100 | −50 |
| 敵人起始條上限 | 20、40、60 | 40 |

- 先掃一維（其他取中心），再掃 `K × h × l` 三維全格（5×4×4＝80 格，600 場）。
- **穩健判準**：中心點及其**所有單參數相鄰格**都落在目標區間 → 穩健；否則標脆弱並給安全範圍。
- 容許 ±10％（沿用 v0.4 敏感度容許）。

### 13.4 不過的處理（預先宣告，驗算者照順序找修正值）

1. 先調 ATB 內部參數：`K`、`h`、`l`、起始條上限、敵人 `W_e`（重擊 120）——**不動 SPEC-02、不動敵人 `dmg`／`hp`**。
2. 內部參數找不到同時落進「起手・平民 20–40％」與「清理級 ≥70％」的格子，才另列 SPEC-02 §10.5 的候選（`pot_hp` 數量、波表）給 mumi 決定（Q-ATB-8）。
3. 目標區間**不得為了湊過而放寬**。

### 13.5 預期（先寫下，驗算用來對照）

窯屍（0.8／手）、亡卒（0.9）比現行「每手 1 次」弱，紅霧妖（1.15）略強；道具 `W=70`、防禦 `W=80` 對你有利。**預期平民存活率會高於 v0.3 的 29.4％**，可能超過 40％。這是這份規格最可能被推翻的地方，所以 §13.4 先規定了調整順序。
