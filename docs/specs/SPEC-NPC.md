## 0. 結論

1. **兩張表**：`D.SEATS`（職位，靜態）＋`S.world.people`（人，存檔）。職位帶功能、見聞、性情、繼任方式；人帶名字、臉、特徵、年齡、氣味、簡歷。
2. **人口**：全局上限 **8,000**、灰窯原 **800**（各鎮上限見 5.1）；居民用「世界種子＋鎮＋序號」重現，**第一次被看到才寫進存檔**。
3. **基本換人（不含定時事件）年率**：現場 **18%**、中層 **9%**、首領 **4%**（v0.2 第 9.2 節的總率去掉「定時事件約一半／三分之一」）；換成每日機率 0.00165／0.00079／0.00034。灰窯原 20 個現場位：每 30 天期望 **0.99 人**變動。
4. **居民年死亡率加權平均 2.35%** → 開局手算全域只算居民每日 **0.157** 人死亡。第二輪（含在任者）：第 1 年死亡 0.1766、進墳場 0.1223；10 年平均 0.1817、進墳場 0.1250（issue #27）。
5. **LOC-NPC 七題**：①人名上不上畫面＝**Q-N1 待 mumi**（建議：第一批照 names-final 只顯示職位名；DEV-NPC 上線後照 v0.2「職位名＋人名」）；②有「外貌傾向」欄 `pres`，**用來過濾名庫**（男向／女向＋中性），不上畫面、不影響稱呼與玩法；③氣味 **80／20**；④綽號**每人至多 1 個**，有職位者 60%、居民 30%，同鎮在世不重複；⑤**老＋姓 ≥50 歲、小＋姓 ≤25 歲**，「阿＋名末字」限流民氣味與難民身分者；名末字兒、子、頭且不符合「小＋姓」者不給親暱稱、熟人叫全名；⑥上限 8,000，**不開三字名**，名庫 727 夠用；⑦世襲**同姓、名 100% 從職位預設氣味抽**，照本地化提案。
6. 待 mumi／製作人的玩法題見第 12 節（Q-N1、Q-N3、Q-N4、Q-N5）。

## 3. 人 `S.world.people`（存檔）

### 3.1 欄位

```
person = {
  pid,                 // 整數，世界內唯一，永不重用
  sur, given,          // 姓、名（LOC 庫；硬規則 2–4 字）
  nick: null | { word, form },   // 綽號（4.4）；form: 'bare'|'word+sur'|'sur+rank'
  rank: null | 1..11,  // 排行（老大…老十、老么）；只單姓
  smell,               // 名字氣味（4.3）
  pres,                // 外貌傾向 'm'|'f'（4.2）；不上畫面
  face,                // 臉種子（整數，ART-NPC 部件拼裝）
  traits: [tag, tag, (tag)],     // 特徵標籤 2–3 個（LOC titles.csv 的 28 個）
  born,                // 出生日（wday，可為負）；age = floor((today − born)/120)
  town, faction,
  seat: null | seatId, // 現職
  status,              // 'on'在任|'acting'代理|'res'居民|'comp'同伴|'jail'被囚|'wanted'通緝中|'missing'|'dead'|'merged'終融|'gone'遷出
  bio: [ {day, ev, seat, by} ],  // 最近 5 筆
  met,                 // 與玩家見面次數
  tie,                 // 與玩家有牽連（殺、舉薦、賄賂、同伴、被通緝、救過）→ 封存時完整保留
  kin: null | pid,     // 世襲用：父母或師承者 pid（只記一層）
  grave: null | graveId
}
```

- 輕記錄（居民、路人）：只存 `pid, seed, town, status, met`＋已被看見的欄位；其他欄位由 `seed` 重算。被深入互動（`met ≥ 3` 或有 `tie`）後長成完整記錄。直白 JSON 實測：輕約 71 字元、完整約 423 字元（第一輪 N7）；經下面的編碼後，8,000 人半輕半完整 84 萬字元。

**存檔編碼（N7 已定，只改編碼、不改欄位）**：採第一輪修正建議 B（精簡鍵名加索引）。DEV-NPC 實作時鍵名可與下表對齊，或另訂等長的短鍵；驗收以 8,000 人半輕半完整 ≤150 萬字元為準（建議 B 實測 842,187）。

| 原則 | 做法 |
| --- | --- |
| 短鍵名 | 完整記錄：`pid,sd,sur,gv,nk,rk,sm,pr,fc,tr,bn,tw,fa,se,st,bio,mt,tie,kn,gvz`（`gvz`＝grave，避開 given 的 `gv`）。輕記錄：`pid,sd,tw,st,mt` |
| 索引值 | 鎮、氣味、特徵標籤、狀態、簡歷事件碼寫整數索引，對 `D` 表；臉、出生日仍是整數 |
| 空欄省略 | 值為 null 或空陣列的鍵不寫出 |
| 簡歷 | 最近 5 筆寫成陣列 `[day, evCode, townIndex]`，不寫物件 |

### 3.2 實體化

- 每鎮居民名額＝`cap(town)`（5.1）。未實體化的居民只是一個計數 `S.world.pop[town].latent`。
- 進入場景要放路人時：從 `latent` 取序號 `k`，用 `wrnd('npc', town, k)` 生成全部欄位 → 寫入存檔、`latent −= 1`。**之後永遠是同一人**（v0.2 PP2 乙）。
- 同場景同時在場者**不同姓**（v0.2 §1）：生成時同場景撞姓就換下一個序號。

## 4. 生成規則（含 LOC-NPC 七題定案）

### 4.1 【LOC 題 1】人名上不上畫面 → **待 mumi（Q-N1）**

查證：v0.2 第 2 節「玩家看到什麼」（mumi 15:02 方向）寫對話框與建築頭「職位名＋人名」、首領與匿名職位只顯示職位名、告示與日誌用全名；names-final 第 150 列（製作人 17:43）寫「除三位固定角色外畫面只顯示 title；name 每局生成」，原因欄寫「照 v0.2」，影響位置是 `data.js NPCS` 與舊人名字串——**是第一批去掉舊人名的處理**。兩者其實是**前後兩期**：第一批還沒有生成器，只能顯示職位名；DEV-NPC 之後才有每局生成的名字可顯示。但「DEV-NPC 之後對話框顯不顯示人名」是玩家看到什麼的取捨，屬玩法，列 Q-N1。

**本檔暫行（Q-N1 甲）**：第一批到 DEV-NPC 前只顯示職位名；DEV-NPC 後對話框與建築頭顯示「職位名　全名」（職位名在前、字大；並排 ≤13 字，LOC 4.4），`takesSurname=false` 或 `anon=true` 的職位只顯示職位名；告示、懸賞令、判決書、世間誌、墓誌銘一律全名。

### 4.2 【LOC 題 2】性別欄 → **有 `pres`（外貌傾向），用來過濾名庫**

- `pres ∈ {m, f}`，各 50%（用 `wrnd`）。**只用在兩處**：①臉部件（ART-NPC 的髮、鬍等部件組）；②名庫過濾：`m` 從「男向＋中性」抽、`f` 從「女向＋中性」抽。
- **不用在**：稱呼（稱呼不分性別，已定）、對白、任何機率或數值、畫面文字。
- 理由：名字與臉同屬「看起來是誰」，臉要分部件時，名字不跟著走會出現臉與名明顯對不上；中性名兩邊都能抽，保留模糊空間。稱呼與玩法完全不看它，所以不違反「稱呼不分性別」。
- 容量（LOC 名庫 727＝男向 315／女向 196／中性 216）：`m` 可抽 531、`f` 可抽 412；最緊的「獵戶×女向」36＋13＝49 名 × 188 姓＝9,212 種，仍遠大於單鎮上限 300。

### 4.3 【LOC 題 3】氣味怎麼掛 → **主氣味 80%＋所在鎮分布 20%**

```
主氣味 primary：
  有職位者 → seat.smell（LOC 職位表第 7 欄）
  無職位但有勢力 → 勢力預設味（下表）
  其他居民、路人 → 由所在鎮分布抽一次當主氣味
抽名時：80% 用 primary；20% 改用「所在鎮分布」再抽一次（可能抽回同味）
世襲繼任 → 100% 用 seat.smell（題 7）
```

| 勢力 → 預設味 | 鎮分布（獵戶／藥童／礦工／逃兵／行商／流民，%） |
| --- | --- |
| 窯幫、礦區 → 礦工；無旗營、白虎軍、破曉 → 逃兵；天星、乘黃 → 行商；百衲會、難民 → 流民；山獵盟 → 獵戶；懸壺社 → 藥童（v0.2 §1） | 灰窯鎮 5／10／35／10／15／25；渡陰關 5／10／5／30／30／20；破曉營 10／5／5／60／0／20；官道驛站 10／5／5／20／40／20；撿骨師營地、鴉巢、其他野外點 15／10／15／20／10／30 |

- 理由：80% 讓「看名字猜出身」成立（礦區多拙實名、軍營多方正名）；20% 讓同一職業不會全是一個味，也反映人會流動。鎮分布照各鎮的主要人群（灰窯礦、渡陰關商與軍、破曉營兵）。
- 【手算】灰窯鎮居民（無勢力）的最終名字氣味：礦工 0.35×0.8＋0.35×0.2＝0.35（主味與混味同分布，結果就是鎮分布本身）；有職位的天星分號掌櫃：行商 0.8＋0.2×0.15＝**0.83**、礦工 0.2×0.35＝0.07、流民 0.05、其餘 0.05。

### 4.4 【LOC 題 4】綽號

| 項目 | 規則 |
| --- | --- |
| 特徵標籤 | 每人 2 個（60%）或 3 個（40%），從 LOC 的 28 個標籤無放回抽；`pres` 不影響 |
| 有沒有綽號 | 有職位者 60%、居民 30%、街頭角色 0（他們本來就只叫職位名） |
| 幾個 | **至多 1 個**，生成時就定（`nick`），終身不變 |
| 從哪個標籤來 | 從自己的特徵標籤裡均勻選 1 個，再從該標籤的綽號詞裡均勻選 1 個 |
| 字形 | `bare` 綽號詞單獨（40%）／`word+sur` 綽號詞＋單姓（如駝背張，40%）／`sur+rank` 單姓＋老＋排行（如周老三，20%，需有 `rank`）；複姓不接排行、改 `bare` |
| 排行 `rank` | 有綽號且抽到 `sur+rank` 時才生：老大 25%、老二 22%、老三 18%、老四 12%、老五 8%、老六至老十共 10%、老么 5% |
| 什麼時候叫出來 | ①街頭傳聞、見聞提到此人；②懸賞令與告示「人稱某某」；③與玩家 `met ≥ 3` 後，日誌與對話開始用。未揭露前畫面不出現 |
| 重複 | **同鎮在世者完整綽號字串不重複**。撞了依序改：`bare`→`word+sur`→換同標籤下一個詞→放棄（無綽號）。死者綽號在世間誌保留，同鎮 8 季內不重用 |

【手算】灰窯鎮上限 300 人、有綽號者約 0.3×280＋0.6×20＝96 人；`bare` 約 38 個，85 個詞平均每詞 0.45 人——`bare` 撞名機率不低（生日問題：38 人取 85 詞，至少一撞約 1 − Π(1−i/85) ≈ 99.9%），所以撞名改 `word+sur` 是常態路徑，**交雲端量放棄率**（判準 ≤10%）。

### 4.5 【LOC 題 5】老／小／阿

| 親暱稱 | 適用 | 誰叫 |
| --- | --- | --- |
| 老＋姓（老周） | 年齡 **≥ 50** 且單姓 | 同輩或年輕的 NPC；玩家 `met ≥ 5` 後的對話與日誌 |
| 小＋姓（小周） | 年齡 **≤ 25** 且單姓 | 年長或上級 NPC；玩家 `met ≥ 5` 後 |

### 5.2 基本換人率（不含定時事件）

```
年率 r（tier）：field 0.18、mid 0.09、head 0.04、street 0.10（街頭角色）
每日機率 h = 1 − (1 − r)^(1/120)
原因分配：死亡 40%｜遷徙 35%｜被取代（通緝、入獄、終融等，由 SPEC-02 事件直接觸發者另計）10%｜升遷 15%
死亡年齡倍率：<40 ×0.5、40–59 ×1.0、≥60 ×2.0；**正規化用當下該 tier 在任者的年齡分布**（每個結算日重算 E[倍率]），讓死亡占換人原因維持 40%

```

【手算】`h`：field 1 − 0.82^(1/120)＝1 − e^(−0.19845/120)＝**0.001652**；mid 1 − e^(−0.09431/120)＝**0.000786**；head 1 − e^(−0.04082/120)＝**0.000340**。灰窯原 20 個現場位 × 30 日 × 0.001652＝**0.99 人／30 日**（v0.2「每 30 日 1–2 人」是含定時事件的總數，基本換人約一半 ✓）。

### 5.5 兩檔模擬精度（v0.2 PP4 乙）

- 玩家所在鎮：每日 `time.newDay` 結算一次。
- 其他鎮：每 30 日（季界）一次，機率用 `1 − (1 − h)^30` 一次判；玩家進入該鎮時補算到今天。
- 實體化的人與 latent 計數用同一套機率；latent 的死亡只減計數、不寫世間誌（沒人認識他）。

### 5.6 世間誌與封存（v0.2 PP3 乙）
