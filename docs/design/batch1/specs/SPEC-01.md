## 0. 結論（先看這裡）

1. **只做兩鎮（灰窯鎮、渡陰關）＋一個盜匪團（斷路幫）。** 每鎮 4 個數字：繁榮 P、財庫 T、治安 O、駐軍 G；區域 1 個數字：匪勢 B。每天跨日時結算一次。
2. **兩個起手值剛好是平衡點。** 起手 P／O／B ＝ 50／55／30（灰窯）、45／60／30（渡陰）；沒有事件、沒有雜訊時，結算一天什麼都不變（第 8.1 節）。不介入的世界靠「獸潮」與「小雜訊」起伏，不是靠起手偏離。
3. **穩定性有手算依據。** 三個主要迴路（P→O→P、O→B→O、P→B→O→P）線性化後的最大特徵值約 0.46（< 1），不會自己放大；加上每日 ±3、向目標回歸 10%、上下限，所以不單向發散（第 8.6 節）。
4. **玩家介入只有三條：資助巡邏（臨時加一檔，100 兩約 2–4 天）、投資巡邏所（3 級，一次買斷）、剿匪（殺劫匪降匪勢）。** 交易稅 5%（只在賣出時扣，Q1 乙已定）。財庫的錢玩家拿不回來，所以不會變成賺錢手段。
5. **不新造數值體系，不改 A-01～A-07。** 趕路只在現有遇險率後面多乘一個「治安／匪勢修正 R」；負重、夜間、獸潮等既有乘項原樣保留。

## 2. 時間與日結掛點（依 SPEC-TIME）

- 日結掛在 `newDay()`（現況 `game.js:418`，由 `passTime` 跨日觸發）。**日界在哪一點、每日幾點結算，一律依 SPEC-TIME；本包不自訂。** 以下所有「每日」＝每個日曆日一次。
- 四時段（清晨 05:00–08:00、白天 08:00–17:00、黃昏 17:00–20:00、黑夜 20:00–05:00）本包只用在一處：**野外遇險的夜暗度與天候倍率依 SPEC-TIME 7.1**（`(1 + mean(w)) × wxRisk`，整段黑夜＝×2，與現況相同），不再用 `isNight` 的出發當下判定。店鋪營業以 SPEC-TIME `isOpen(bid,t)` 判定；日結與交易稅不受影響（打烊時本來就不能交易）。本包的日結用 00:00 日界（`newDay`）；SPEC-02／03 的每日計數用 05:00 起算的 `wday`，兩者並存（SPEC-TIME Q6 甲）。
- 若一次 `passTime` 跨過 ≥ 2 個日界（現況最長單次小於 24 小時，不會發生；之後若有長睡眠或長旅程會發生），**必須逐日補算**，不得只算一次。實作建議：`newDay(day)` 帶日期參數，迴圈 `for d = startDay+1 … endDay`。「月」＝ 30 天（程式沒有月曆，等於一季）。
- 不模擬「玩家不在的過去」：載入缺少 `world.towns` 的存檔時，以起手值初始化，不回補（無舊檔相容需求，不寫遷移）。

## 5. 每日結算流程（`newDay`，逐鎮、逐區域）

**原則：用「昨日結束時」的 P、O、B、crew 算今日所有目標與稅，算完一起寫回（同步更新，不是邊算邊用新值）。**

順序（對應現況 `newDay`：先 `worldTick`，後 `restockShops`、`questTick`、`rumorTick`）：

1. `worldTick(day)`〔既有，擴充〕：獸潮結束時判結果（5.4）、開始時抽目標鎮。
2. `townTick(day)`，每鎮依序：5.1 稅 → 5.2 軍費與實際駐軍 → 5.3 目標與更新 → 5.5 上繳。
3. `regionTick(day)`：5.6 匪勢與人手。
4. `restockShops()`（使用 `townHurt`）、`questTick`（用 4.9 權重；並依 5.9 貼出當日排定的救援委託）、`rumorTick`（用 4.9 權重）〔既有流程，只換權重〕。
4b. `refugeeTick(day)`：5.10 難民棚人口。
5. 寫 `brief`（第 7 節）。

### 5.1 稅

`T += Inc`（見 4.3）。玩家交易稅在賣出當下就進 `T`，不等日結。

### 5.2 軍費與實際駐軍

```
# 5.1 已用目前的 taxCut 算過 Inc；之後才遞減計數器
rescueCd = max(rescueCd-1, 0); taxCut = max(taxCut-1, 0)
need = UPKEEP[Gnom]
if T >= need:                       # 付得起
    T -= need; Geff = Gnom; debt = 0
    d = UPKEEP[min(Gnom+1,3)] - need
    if Gnom < 3 and F >= d:         # 資助加派一檔
        F -= d; Geff = Gnom + 1
else:                               # 欠餉
    Geff = max(Gnom - 1, 0)
    pay = min(T, UPKEEP[Geff]); T -= pay
    debt += 1                       # F 不動
if debt >= 3 and rescueCd == 0:     # 求援
    T += 6*UPKEEP[Gnom]; debt = 0; taxCut = 10; rescueCd = 20
# 計數器遞減已在本段最前面做完（見上），求援設的 taxCut = 10 從隔天起連續 10 天各抽 20%
```

註：計數器（`rescueCd`、`taxCut`）在算完 `Inc` 之後、軍費判斷之前各減 1，所以求援設定 `taxCut = 10` 後，隔天起剛好連續 10 個日結的 `Inc` 乘 0.8。`F` 剩餘不足一檔差額時留著，下次捐款補足；`F` 不過期。

### 5.3 繁榮與治安更新

```
P* = P_base + 0.40*(O - O_base)
O* = O_base + 0.20*(P - P_base) - 0.20*(B - 30) + 10*(Geff - G0) + PATROL[Lpat]
tideP, tideO = 0, 0
if 目標鎮且今日在獸潮期:  tideP -= 2; tideO -= 1
if townHurt(tid):          tideP -= 2; tideO -= 1
if 今日擊退成功(玩家或自衛): tideP += 3; tideO += 2
dP = 0.10*(P* - P) + eps + tideP        # eps 見 PNOISE
dO = 0.10*(O* - O) + tideO - (tid=='duyin' ? 0.2*refugee.soldToday : 0)   # 販人回饋：上次日結以來成交人數，5.10
dP = clamp(dP, -3, 3); dO = clamp(dO, -3, 3)
if dP > 0 and P > 70: dP *= 0.5
P = clamp(P + dP, 15, Pcap); O = clamp(O + dO, 0, 100)
```

`P`、`O`、`B` 在式中一律是「昨日結束值」；`Geff` 是今日剛算出的值。

### 5.4 獸潮連動（擴充 `worldTick`）

獸潮結束日（`day > W.tide.end`）判結果：

```
repelled = (玩家殺滿 need 頭)  or  (wrnd('tide', day) < P_DEF[Geff_yesterday])
if repelled:  今日該鎮 tideP += 3, tideO += 2；若玩家殺滿，賞金委託照舊（〔既有〕）
else:         W.hurt[town] = day + hurtDays - 1；〔既有〕撕榜與日誌；hurtDays = (Geff_yesterday>=2 ? 1 : 2)
```

- `Geff_yesterday`：該鎮上一次日結寫入的 `Geff`（因為 `worldTick` 在 `townTick` 之前）。
- 自衛擊退成功時日誌：「守軍擋下了獸潮。」；玩家沒殺滿不領賞金，賞金委託照〔既有〕被撕榜。
- 獸潮下一次的間隔、抽目標鎮改用 `wrnd`（E4）；目標鎮權重見 4.7。
- 〔既有〕獸潮效果（野徑遇險 ×1.5、藥水 ×1.5、獸跡 +1、`startEvent` 60% 獸跡）全部保留。

### 5.10 難民人口守恆與人手池接口（給 SPEC-03）

渡陰關內難民棚人口由本包記帳，SPEC-03 的牙行「人手池」只從這裡取人。

```
S.world.refugee = { camp: 60, inTotal: 0, settledTotal: 0, soldTotal: 0, soldToday: 0, soldYday: 0 }
每日日結（00:00，townTick 之後）：
  arrive = REF_IN + REF_HURT × (今日受創的鎮數)        # 3 + 1×(0–2)
  settle = floor(camp / 20)                             # 安頓進關內，成為居民（MVP 不加 P）
  camp  += arrive − settle;  inTotal += arrive;  settledTotal += settle
  soldYday = soldToday;  soldToday = 0
販人成交（SPEC-03，任何時刻）：refugeeSold(n)：n ≤ camp 才可成交；camp −= n；soldTotal += n；soldToday += n
守恆式（任何時刻恆成立）：camp + settledTotal + soldTotal = 60 + inTotal
```

- 常數〔新〕：`REF0 = 60`、`REF_IN = 3`／日、`REF_HURT = 1`／受創鎮日、`settle = floor(camp/20)`。不介入時固定點：`floor(60/20) = 3 = REF_IN`，camp 穩定在 60–**82**（v0.3：上界 79→82。理論上界 79+5−3 = 81；camp 在 80–82 時 `settle = 4`、當日 `arrive ≤ 5`，再多 1。S1 驗算 360 天延伸最大值為 80）。
- **人手池**（SPEC-03 10.10，`renlu.pool`）是 camp 的「可被牙行接觸的子集」，不是另一群人：每個 `wday` 05:00 `pool = min(24, pool + 3, camp)`；camp 因安頓或成交降到低於 pool 時，`pool = camp`。成交 n 人時 `pool −= n` 且呼叫 `refugeeSold(n)`。
- **回饋**〔新〕：渡陰關 `dO` 在 5.3 加一項 `−0.2 × soldToday`（上次日結以來成交人數；townTick 先用，refugeeTick 再把它移到 `soldYday`；在 ±3 上限之前）。手算：長期每日賣 3 人（人手池補充上限）→ 每日 −0.6 → 穩態 `δO ≈ −0.6 / 0.10 / 0.862 ≈ −7.0`、`δP ≈ −2.8`。待雲端驗算（SPEC-03 9.4 第 5 項）。
- 長期可持續的販人量 ≈ `REF_IN = 3` 人／日；之上會把難民棚掏空（camp → 0 後只剩每日新到的 3 人）。

### 7.2 財庫收支（兩個合計＋淨額）

結算日 d 的 `brief` 記錄「上一次日結之後到本次日結為止」這 24 小時進出 `T` 的全部金額（含前一日白天的交易稅、罰金與賞金，加上本次日結的稅、軍費、求援、上繳）。UI 上的「今日」即指這段。

| 欄位 | 內含項目（全部是進出 `T` 的錢） |
| --- | --- |
| `treasuryIn`（今日收入合計） | ① 基礎稅 `Inc`（已含抽成 ×0.8，5.1）＋② 當日交易稅合計 `tax`（5.7，賣出所得 5%，Q1 乙）＋③ 罰金與贖款 `fines`（SPEC-02：入城罰金 `GATE_FINE`、繳罰金消案 `PAYOFF`、贖罪 `PAROLE_COST`，回該鎮財庫）＋④ 求援撥款 `rescueAmt`（`6×UPKEEP[Gnom]`，只在求援日） |
| `treasuryOut`（今日支出合計） | ① 實付軍費 `upkeepPaid`（欠餉時為實付）＋② 賞金實付 `bountyPaid`（SPEC-02 5.5：`min(BOUNTY, T)`）＋③ 上繳 `overflow`（5.5） |
| `treasuryNet`（今日淨額） | `treasuryIn − treasuryOut` |

- **不含**：資助款。玩家捐的錢進 `F`（指定軍費），不進 `T`，加派時也從 `F` 扣（5.2）；所以資助不出現在財庫收支，只出現在駐軍狀態與 `brief.aidFund`。
- **取整**：三個欄位在寫 `brief` 時各自四捨五入成整數，且 `treasuryNet` 用取整後的兩數相減（UI 看到的三數永遠對得上）。與 `T` 的實際變動可能差 ≤ 1 兩，`brief.dT`（兩位小數）保留實際值供測試。
- **灰窯起手第 1 天手算**（無事件、無玩家）：`Inc = 22.96`、交易稅 0、罰金 0、求援 0 → `treasuryIn = 23`；軍費 15、賞金 0、上繳 0 → `treasuryOut = 15`；`treasuryNet = +8`；現額 `T = 207.96` → 顯示 208；`dT = 7.96`。同日玩家若在灰窯賣出 100 兩：交易稅 5 → `treasuryIn = round(27.96) = 28`、`treasuryNet = +13`。（v0.3：隨 `K_TAX` 0.56 重算；v0.2 為 `Inc = 18.45`、In 18、Net +3、T 203.45。【手算，未經模擬】）

### 7.3 財庫分檔 `treasuryTier`（收合短語用）

| --- | --- | --- | --- | --- |
| 1 | `debt` | 今日欠餉（`debtToday`） | 欠餉 | — |
| 2 | `full` | `T ≥ T_CAP`（含今日有上繳） | 滿庫 | ≥ 1350 ／ ≥ 3600 |

### 7.4 求援與抽成的可見性

- `rescueCd`（冷卻）不顯示。

### 7.5 因果句主因（方向一致規則）

1. `brief.trend === 'flat'`（`|dP| < 0.5`）：`whyCode = null`，不出因果句。
2. 否則依下表序號由上往下，取**第一個「條件成立且方向與 `trend` 相同」**的代碼。方向 `−` 的原因只能解釋「降」，`+` 只能解釋「升」；**不會出現「繁榮升，因獸潮壓境」**。
3. 都不成立時：若 `dP` 與 `(P* − P昨)` 同號（朝常態回穩）→ `WHY_REVERT`；否則 `WHY_NONE`（市面小起落，即 PNOISE）。

| 序 | 條件 | 方向 | 因果代碼 |
| --- | --- | --- | --- |
| 1 | 該鎮今日在獸潮期 | − | `WHY_TIDE` |
| 2 | 該鎮受創中 | − | `WHY_HURT` |
| 3 | 今日擊退成功 | + | `WHY_REPEL` |
| 4 | 今日欠餉降檔（`debtToday`） | − | `WHY_DEBT` |
| 5 | `B ≥ 35`（猖獗以上） | − | `WHY_BANDIT` |
| 6 | 渡陰關昨日有人被賣（`refugee.soldYday > 0`，5.10） | − | `WHY_RENLU` |
| 7 | 今日資助加派中（`aidToday`） | + | `WHY_AID` |
| 8 | 治安昨日變動 ≥ +1 | + | `WHY_ORDER_UP` |
| 9 | 治安昨日變動 ≤ −1 | − | `WHY_ORDER_DOWN` |
| 10 | 其餘、與 P* 同向 | ± | `WHY_REVERT` |
| 11 | 其餘 | ± | `WHY_NONE` |

例：獸潮日 `dP = +0.6`（回歸與雜訊抵過 −2 的情形極少，但會發生）→ 序 1 方向不符、跳過 → 若沒有其他「+」原因 → 看是否朝 P* 回穩，給 `WHY_REVERT` 或 `WHY_NONE`。

## 8. 手算驗證（只用算式；不是模擬結果）

### 8.1 起手日（無雜訊、無事件）

- **灰窯**：`Inc = 0.56 × 50 × (0.6 + 0.004×55) = 0.56 × 50 × 0.82 = 22.96`；軍費 15；`T = 200 + 22.96 − 15 = 207.96`；淨額 **+7.96**。（v0.3；v0.2 的 `K_TAX = 0.45` 為 18.45／203.45／+3.45）
  `P* = 50 + 0.4×(55−55) = 50`；`O* = 55 + 0.2×0 − 0.2×0 + 10×0 + 0 = 55`；`B* = 30 − 0.5×(57.5−57.5) − 0.2×(47.5−47.5) + 0 + 5×0 = 30`。三者皆不動。
- **渡陰**：`Inc = 1.45 × 45 × (0.6 + 0.004×60) = 1.45 × 45 × 0.84 = 54.81`；軍費 40；淨額 **+14.81**；`T = 300 + 14.81 = 314.81`。（v0.3；v0.2 的 `K_TAX = 1.15` 為 43.47／+3.47／303.47）`P* = 45 + 0.4×0 = 45`；`O* = 60`。
- 上繳線：灰窯 `90×15 = 1350`、渡陰 `90×40 = 3600`。灰窯從 200 補到 1350 需 `1150 / 7.96 ≈ 144` 天，**120 天內不會上繳**（第 9 節 E6；v0.2 為 333 天）；渡陰從 300 補到 3600 需 `3300 / 14.81 ≈ 223` 天。（v0.3 隨 `K_TAX` 重算；實際有雜訊與軍費欠付，以 S1 為準：`T` 最高只到上限的 48.976%，v0.2 值下）

### 8.2 資助 100 兩（灰窯，`Gnom = 1`，無雜訊）

- 差額 `d = 40 − 15 = 25`；100 兩可加派 `100 / 25 = 4` 天〔LW 「約撐 2–4 天」的下緣〕。渡陰（2→3）`d = 90 − 40 = 50` → `100 / 50 = 2` 天（上緣）。**LW 的 2–4 天由 UPKEEP 推得，兩者吻合。**
- 日 1：`Geff = 2`，`O* = 55 + 10 = 65`，`ΔO = 0.10×(65−55) = +1.00` → O = 56.00；`P* = 50 + 0.4×0 = 50`，ΔP = 0。
- 日 2：`P* = 50 + 0.4×(56−55) = 50.4`，`ΔP = 0.10×0.4 = 0.04` → P = 50.04；`O* = 55 + 0.2×0 + 10 = 65`，`ΔO = 0.10×(65−56) = +0.90` → O = 56.90。
- 日 3：`P* = 50 + 0.4×1.9 = 50.76`，`ΔP = 0.10×(50.76−50.04) = 0.072` → 50.112；`O* = 65 + 0.2×0.04 = 65.008`，`ΔO = 0.10×(65.008−56.90) = 0.811` → **O = 57.71**。

### 8.3 獸潮日（灰窯，`Geff = 1`，無雜訊，起手狀態）

- 獸潮開始日：`ΔP = 0.10×(50−50) − 2 = −2.00` → P = 48.00；`ΔO = −1.00` → O = 54.00。
- 第二日：`P* = 50 + 0.4×(54−55) = 49.6`，`ΔP = 0.10×(49.6−48) − 2 = −1.84` → 46.16；`O* = 55 + 0.2×(48−50) = 54.6`，`ΔO = 0.10×(54.6−54) − 1 = −0.94` → 53.06。
- 結束日判結果：灰窯 `P_DEF[1] = 0.30`。**失敗**（機率 0.70）：受創 2 天，每日 `ΔP −2、ΔO −1` 再加；累計約 `ΔP −8`、`ΔO −4`（先不計回歸）。**成功**（0.30）：當日 `ΔP +3、ΔO +2`；累計 `−4 + 3 = −1`。
- 渡陰 `Geff = 2`：`P_DEF[2] = 0.55`，受創 1 天。失敗累計 `ΔP −6`、成功 `−1`。

### 8.4 不介入時的平均水位（粗估，待雲端驗算）

- 獸潮循環：間隔 5–7 天＋持續 2 天，平均每 8 天一次；120 天約 15 次，兩鎮各約 7.5 次〔均分〕。

### 8.5 巡邏所長期效果（單鎮線性化：`δP = 0.4δO`、`δB = −0.29δO`）

- `δO = x + 0.2×δP − 0.2×δB = x + 0.08δO + 0.058δO` → `δO = x / 0.862`。
- Lv1 `x=5` → δO ≈ **+5.8**；Lv2 `x=9` → **+10.4**；Lv3 `x=12` → **+13.9**（灰窯起手 55 → 約 69）。同理「長期維持資助一檔」`x=10` → +11.6。
- 對遇險率（灰窯 Lv3：`δŌ = 13.9/2 = 6.96`、`δB = −0.29×13.9 = −4.04`）：`R_road = 1 − 0.015×6.96 = 0.896`；`R_wild = 1 + 0.012×(−4.04) − 0.010×6.96 = 0.882`。野徑單段 `22% × 0.882 = 19.4%`；官道 `4% × 0.896 = 3.6%`。
- 最大化（Lv3＋資助同時）：`x = 22` → δO ≈ 25.5，O ≈ 80.5，才剛碰到 > 80 的「太好」條款。**設計意圖**：一個鎮砸 1000 兩，野徑遇險從 22% 降到約 19%，「路上少了點事」但不是無敵；`R` 下限 0.5。強度：Q5 甲已定維持現值，雲端驗算後再調。

### 8.6 穩定性（為何不發散）

- 取兩鎮對稱模式（最大特徵值所在）。目標對狀態的偏導矩陣（列：P\*、O\*、B\*；行：P、O、B）為
  `K = [[0, 0.4, 0], [0.2, 0, −0.2], [−0.2, −0.5, 0]]`。
- 特徵多項式：`λ³ − (ce + ab)λ − acd = λ³ − 0.18λ − 0.016 = 0`（a = 0.4、b = 0.2、c = 0.2、d = 0.2、e = 0.5）。
- `λ = 0.463` 代入：`0.0993 − 0.0833 − 0.016 = 0.0000`。另兩根乘積 `0.016/0.463 = 0.035`，模長約 0.19。反對稱模式（兩鎮一升一降，B 不動）：`λ² = ab = 0.08`，`λ = 0.283`。**最大特徵值約 0.46 < 1：目標自己的回饋迴路不會放大。**
- 每日以 `K_REG = 0.10` 向目標靠攏：日映射特徵值 `1 + 0.10×(0.463 − 1) = 0.946`，半衰期 `ln0.5 / ln0.946 ≈ 12.5` 天。
- 因此「同一衝擊」的最長影響 ≈ 兩個半衰期（25 天）仍留 25%。這也是 120 天驗收能容納數次獸潮的原因。
- 死亡螺旋最壞固定點（欠餉＋匪勢高）：`Geff = 0`（欠餉降一檔）、迭代 `P* = 50 + 0.4(O−55)`、`O* = 55 + 0.2(P−50) − 0.2(B−30) − 10`、`B* = 30 − 0.5(O−57.5) − 0.2(P−47.5)` → 約 `P ≈ 44.5、O ≈ 42、B ≈ 38`（以灰窯為例，遠高於底線 15）。此時軍費 0（`Geff = 0`），財庫 `+Inc ≈ +15`／日，約 1–2 天就付得起 15 而脫離欠餉。**結論：參數下沒有「掉到底線出不來」的固定點；`P_MIN = 15` 與求援是保險。**
